Build production-ready workflows that continue when optional steps fail and leave an execution trace for debugging.

<Note>
As of PraisonAI [#4334](https://github.com/MervinPraison/PraisonAI/pull/4334) (2026-08-25), `skip_on_failure=True` and `on_error="continue"` are honored across every failure-cascade path (`AgentTeam` sync + async, `AgentFlow`, `Process.sequential` / `asequential`). Previously these flags were inert on cascade paths and dependents were force-failed the moment any upstream dependency failed. If you were working around this by removing `context=[...]` dependencies, you can put them back.
</Note>

```python
from praisonaiagents import Agent, Task, AgentFlow

researcher = Agent(name="researcher", instructions="Research topics thoroughly")
enricher = Agent(name="enricher", instructions="Add real-world examples")

workflow = AgentFlow(
    steps=[
        Task(description="Research AI trends", agent=researcher, max_retries=3, retry_delay=1.0),
        Task(description="Add examples", agent=enricher, skip_on_failure=True, retry_delay=0.5),
    ],
    history=True,
)
result = workflow.start("AI agents 2025")
```

The user starts a multi-step workflow; optional steps can fail without aborting the run, with execution history for debugging.

## How Graceful Degradation Now Works

A dependent task that opts in still runs even when an upstream dependency in its `context` fails.

```python
from praisonaiagents import Agent, Task, AgentTeam

researcher = Agent(name="researcher", instructions="Research topics")
enricher   = Agent(name="enricher",   instructions="Add examples")

research = Task(name="research", action="Research AI trends", agent=researcher)
enrich   = Task(
    name="enrich",
    action="Add real-world examples",
    agent=enricher,
    context=[research],
    skip_on_failure=True,     # or on_error="continue"
)

team = AgentTeam(agents=[researcher, enricher], tasks=[research, enrich])
team.start()   # even if `research` fails, `enrich` still runs (in degraded mode)
```

## Equivalent Flags

Two flags opt into graceful degradation — pick either one.

```mermaid
graph TB
    Start{Need a dependent<br/>to keep running?} --> Legacy[skip_on_failure=True]
    Start --> Rich[on_error=continue]
    Legacy --> Continue[Dependent runs<br/>in degraded mode]
    Rich --> Continue
    Start -->|Default| Stop[on_error=stop<br/>workflow fails]

    classDef config fill:#6366F1,stroke:#7C90A0,color:#fff
    classDef success fill:#10B981,stroke:#7C90A0,color:#fff
    classDef fail fill:#8B0000,stroke:#7C90A0,color:#fff

    class Legacy,Rich config
    class Continue success
    class Stop fail
```

- `skip_on_failure=True` — legacy boolean, still works, means "keep the workflow moving".
- `on_error="continue"` — richer three-state field (`"stop"` / `"continue"` / `"retry"`). Prefer this in new code.
- Either flag alone is enough; setting both is redundant but harmless.

## Configuration Options

| Param | Type | Default | Description |
|-------|------|---------|-------------|
| `skip_on_failure` | `bool` | `False` | Continue workflow if this task fails (legacy; equivalent to `on_error="continue"`). |
| `on_error` | `str` | `"stop"` | Failure behaviour: `"stop"` fails the workflow, `"continue"` keeps it running (equivalent to `skip_on_failure=True`), `"retry"` retries per `max_retries`. |
| `retry_delay` | `float` | `0.0` | Seconds between retries. |
| `max_retries` | `int` | `3` | Maximum retry attempts. |
| `history` | `bool` | `False` | Enable execution trace on `AgentFlow`. |

## Task Parameters

### skip_on_failure

```python
task = Task(
    description="Optional data enrichment",
    skip_on_failure=True,
    agent=enricher,
)
```

### on_error

```python
task = Task(
    description="Optional data enrichment",
    on_error="continue",   # "stop" | "continue" | "retry"
    agent=enricher,
)
```

### retry_delay

```python
task = Task(
    description="API call with rate limiting",
    retry_delay=2.0,
    max_retries=5,
    agent=api_agent,
)
```

## Workflow History

```python
workflow = AgentFlow(steps=[task1, task2], history=True)
result = workflow.start("input")

for entry in workflow.get_history():
    print(f"{entry['step']}: {'ok' if entry['success'] else 'failed'}")
    if entry.get("error"):
        print(f"  Error: {entry['error']}")
```

| Field | Type | Description |
|-------|------|-------------|
| `step` | `str` | Step or agent name |
| `timestamp` | `str` | ISO timestamp |
| `success` | `bool` | Whether the step succeeded |
| `output` | `str` | Truncated output (500 chars) |
| `error` | `str` | Error message if failed |

## Conditional Branching

```python
from praisonaiagents import AgentFlow, when

workflow = AgentFlow(steps=[
    scorer_agent,
    when(
        condition="{{score}} > 80",
        then_steps=[approve_agent],
        else_steps=[reject_agent],
    ),
])
```

<Warning>
`if_()` is deprecated. Use `when()` instead.
</Warning>

## Best Practices

<AccordionGroup>

<Accordion title="Mark optional steps with skip_on_failure">

Enhancement and enrichment tasks should not block the main workflow path.

</Accordion>

<Accordion title="Use higher retry_delay for rate-limited APIs">

Set `retry_delay=2.0` or more when calling external APIs with throttling.

</Accordion>

<Accordion title="Enable history during development">

Always set `history=True` while building workflows — inspect `get_history()` after failures.

</Accordion>

<Accordion title="Separate critical from optional in YAML">

Keep required steps strict (`skip_on_failure: false`) and flag enrichers as optional explicitly.

</Accordion>

</AccordionGroup>

Generate images from natural language descriptions with PraisonAI Image Agents — sync or async, with DALL-E integration out of the box.


```python
from praisonaiagents import ImageAgent

agent = ImageAgent(llm="dall-e-3")
agent.chat("A minimalist logo for a coffee shop")
```

The user describes an image; the image agent calls the generation API and returns a URL.

## Default models

`ImageAgent` picks an image-capable default when you don't pass `llm=`. `generate()` uses `dall-e-3`; `edit()` and `variation()` use `dall-e-2` because dall-e-3 does not support those endpoints. Pass `llm=` to override.

Reference: [PR #5948](https://github.com/MervinPraison/PraisonAI/pull/5948), fixes [#5944](https://github.com/MervinPraison/PraisonAI/issues/5944).

```python
agent = ImageAgent()

```

Set `OPENAI_API_KEY` in your environment before running. Uses `dall-e-3` by default.

</Step>

<Step title="With Explicit Model">

```python
from praisonaiagents import ImageAgent

agent = ImageAgent(llm="dall-e-3")

print(result)
```

Swap in any image model, e.g. `llm="openai/gpt-image-1"`.

</Step>

<Step title="With Configuration">

```python
import os
from praisonaiagents import ImageAgent

agent = ImageAgent(
    name="ImageCreator",
    llm="dall-e-3",
    style="natural",
)

result = agent.chat("A minimalist logo for a coffee shop")
print(result)
```

</Step>

<Step title="Async">

```python
import asyncio
import os
from praisonaiagents import ImageAgent

async def main():
    agent = ImageAgent(name="ImageCreator", llm="dall-e-3", style="natural")
    result = await agent.achat("A cute baby sea otter playing with a laptop")
    print(result)

asyncio.run(main())
```

<Note>
`achat()` is genuinely non-blocking as of [PR #5219](https://github.com/MervinPraison/PraisonAI/pull/5219) — the image round-trip runs on a worker thread, not the event loop. See [Non-blocking async](#non-blocking-async-pr-5219) below.
</Note>

</Step>

</Steps>

Install with LLM support: `pip install "praisonaiagents[llm]"`

## Non-blocking async (PR #5219)

`ImageAgent.agenerate_image`, `agenerate`, `aedit`, `avariation`, and (transitively) `achat` now offload the synchronous image call via `asyncio.to_thread`, so awaiting one no longer freezes the event loop for the 10–60 second image round-trip.

Reference: [PR #5219](https://github.com/MervinPraison/PraisonAI/pull/5219), fixes [#5162](https://github.com/MervinPraison/PraisonAI/issues/5162).

Run an `ImageAgent` and a text-only `Agent` side by side — the text agent keeps streaming while the image generates:

```python
import asyncio
from praisonaiagents import Agent, ImageAgent

img_agent = ImageAgent(name="ImageCreator", llm="dall-e-3", style="natural")
text_agent = Agent(name="Writer", instructions="Write a short product blurb.")

async def main():
    # Before PR #5219 the image call ran inline on the loop thread and
    # silently starved the text agent for the whole 10–60s round-trip.
    # Now both run concurrently.
    image, blurb = await asyncio.gather(
        img_agent.achat("A minimalist logo for a coffee shop"),
        text_agent.achat("Describe a cozy neighbourhood coffee shop"),
    )
    print(image)
    print(blurb)

asyncio.run(main())
```

<Warning>
This fix landed for `ImageAgent` **only**. `VideoAgent` (`astart`, `adownload`) and `AudioAgent` (`atranscribe`) still run their synchronous call inline on the event loop as of PR #5219 and will block a concurrent `gather`. If a follow-up PR offloads them, this warning will be updated.
</Warning>

## Supported image models

`ImageAgent` works with any image model exposed through LiteLLM. The capability layer (`image_generate` / `image_edit`) automatically drops parameters the target model rejects — notably `response_format` on `dall-e-3` and `gpt-image-*` — so you do not have to special-case them yourself.

`ImageAgent` also drops `style` on OpenAI image models other than `dall-e-3` (such as `dall-e-2` and `gpt-image-1`), which reject it. Switching from `dall-e-3` to `gpt-image-1` is a one-line `llm=` change.

References: [PR #5346](https://github.com/MervinPraison/PraisonAI/pull/5346) (`response_format`), [PR #6077](https://github.com/MervinPraison/PraisonAI/pull/6077) (`style`), fixes [#5339](https://github.com/MervinPraison/PraisonAI/issues/5339) and [#6076](https://github.com/MervinPraison/PraisonAI/issues/6076).

## Best Practices

<AccordionGroup>

<Accordion title="Use environment variables for API keys">
Read `OPENAI_API_KEY` from the environment — never hardcode keys in source files.
</Accordion>

<Accordion title="Pick the right model">
Use `dall-e-3` for quality; switch models via the `llm` parameter when cost or speed matters more.

Omit `llm=` to use the built-in default (`dall-e-3` for generate, `dall-e-2` for edit/variation).
</Accordion>

<Accordion title="Prefer async in web apps">
Use `achat()` when serving multiple concurrent image requests from a FastAPI or gateway handler.
</Accordion>

<Accordion title="Describe style explicitly">
Pass `style="natural"` or `style="vivid"` on `dall-e-3` for consistent visual output across runs. For other OpenAI image models (`dall-e-2`, `gpt-image-1`), put style cues in the prompt instead — `style` is not supported there and `ImageAgent` drops it automatically.
</Accordion>

</AccordionGroup>

# Sandbox Execution

`SandboxExecutor` (`praisonai_code.cli.features.sandbox_executor`) checks command text against deny lists and runs the command on the **host** as the current user — it is a guard rail against mistakes, **not** isolation and **not** a security boundary.

<Warning>
**Not a security boundary.** Every `SandboxExecutor` mode (`basic`, `strict`, `network_isolated`) filters the command text and runs it directly on your host as your OS user. Mode names describe which commands are filtered, not isolation. For untrusted or model-generated code, use `PRAISON_SHELL=sandboxed praisonai code` or an isolating backend from `praisonai-sandbox` (`docker`, `sandlock`, `e2b`, `modal`, `daytona`, `novita`). See [Threat Model](/features/threat-model).
</Warning>

<Warning>
No CLI flag routes agent commands through this executor. The legacy `praisonai "…" --sandbox off|basic|strict` flag is **display-only** and prints: "`--sandbox` is not enforced here; commands run uncontained. Use `praisonai code` with `PRAISON_SHELL=sandboxed` for OS-level containment." The modes below apply only when you call `SandboxExecutorHandler` / `SubprocessSandbox` from Python.
</Warning>

<Note>
The `praisonai code` coding agent has its own **OS-level** containment for every shell command — Seatbelt (macOS) or `bwrap` (Linux), driven by [`PRAISON_SHELL=sandboxed`](/features/praison-shell). It is the path that actually runs on macOS today, distinct from `SandboxConfig.native()` (Linux-only `sandlock`). See [OS Sandbox](/features/os-sandbox).
</Note>

## Overview

Each `SandboxExecutor` run applies:
- **Command deny-list filtering** — refuses blocked commands (`rm`, `sudo`, shells like `sh`/`bash`, etc.) and dangerous patterns
- **`shell=False` and minimal environment** — runs directly without a shell and passes a reduced env
- **Resource limits** — wall-clock timeout, CPU-time and file-size limits (plus memory limit on Linux)
- **Network tool deny-list** — refuses common network tools (`curl`, `wget`, `nc`, `ssh`, `python`, `node`, etc.) in `network_isolated` mode (does **not** create a network namespace)
- **Temporary working directory** — runs in a temporary directory in `strict` mode (settings a host subprocess cannot enforce, such as non-empty `allowed_hosts`, raise an error instead of silently pretending)

## Quick Start

```bash
# Real OS-level containment for the coding agent
PRAISON_SHELL=sandboxed praisonai code
```

```python
# Host-side command filter from Python
from praisonai.cli.features import SandboxExecutorHandler

handler = SandboxExecutorHandler()
handler.initialize(mode="basic")
print(handler.execute("echo hello").stdout)
```

## Filter Modes

Mode names are kept for backward compatibility; every mode runs the command on the host.

### Disabled (Default)

No filtering. Commands run directly.

### Basic

Deny-listed commands, patterns, and paths are refused with resource limits:

```python
handler.initialize(mode="basic")
```

**Applied checks:**
- 512 MB memory limit (Linux), 60 s CPU/timeout limit
- Blocks dangerous commands (`rm`, `rmdir`, `mv`, `dd`, `sudo`, `sh`, `bash`, etc.) and blocked paths
- Network tools allowed

### Strict

Adds network tools to the deny list and runs in a temporary working directory on the host:

```python
handler.initialize(mode="strict")
```

**Applied checks:**
- 256 MB memory limit (Linux), 30 s CPU/timeout limit, max 5 processes
- Blocks dangerous commands plus network tools (`curl`, `wget`, `nc`, `netcat`, `ssh`, `scp`)
- Runs in a temporary working directory (host filesystem still exists — not a container or chroot)

### Network Isolated

Same as `basic`, plus refuses commands in `NETWORK_COMMANDS` (`curl`, `wget`, `nc`, `ssh`, `scp`, `python`, `python3`, `node`, `ruby`, `perl`, `openssl`, etc.). Passing a non-empty `allowed_hosts` raises an error because a host subprocess cannot enforce host-level firewalling.

```python
handler.initialize(mode="network_isolated")
```

**Applied checks:**
- 512 MB memory limit (Linux), 60 s CPU/timeout limit
- Blocks dangerous commands and `NETWORK_COMMANDS` on the command line (no kernel network namespace)

## Python API

### Basic Usage

```python
from praisonai.cli.features import SandboxExecutorHandler

# Initialize with a mode
handler = SandboxExecutorHandler()
sandbox = handler.initialize(mode="basic")

# Execute a command
result = handler.execute("echo 'Hello, World!'")

print(f"Success: {result.success}")
print(f"Output: {result.stdout}")
print(f"Was sandboxed: {result.was_sandboxed}")
```

### Execution Result

```python
result = handler.execute("ls -la")

# Result properties
print(f"Success: {result.success}")
print(f"Exit code: {result.exit_code}")
print(f"Stdout: {result.stdout}")
print(f"Stderr: {result.stderr}")
print(f"Duration: {result.duration_ms}ms")
print(f"Sandboxed: {result.was_sandboxed}")
print(f"Violations: {result.policy_violations}")
```

### Command Validation

```python
# Validate before executing
violations = handler.validate_command("rm -rf /")

if violations:
    print("Command blocked:")
    for v in violations:
        print(f"  - {v}")
else:
    result = handler.execute("rm -rf /")
```

### Custom Policy

```python
from praisonai.cli.features.sandbox_executor import (
    SandboxPolicy,
    SandboxMode,
    SubprocessSandbox
)

# Create custom policy
policy = SandboxPolicy(
    mode=SandboxMode.BASIC,
    max_memory_mb=1024,
    max_cpu_seconds=120,
    max_file_size_mb=50,
    max_processes=20,
    allow_network=True,
    blocked_commands={"rm", "sudo", "chmod"},
    blocked_paths={"/etc", "/var", "/usr"}
)

# Use custom policy
sandbox = SubprocessSandbox(policy=policy)
result = sandbox.execute("my_command")
```

## Blocked Commands

By default, these commands are blocked:

| Command | Reason |
|---------|--------|
| `rm` | File deletion |
| `rmdir` | Directory deletion |
| `mv` | File moving (can overwrite) |
| `dd` | Disk operations |
| `mkfs` | Filesystem creation |
| `fdisk` | Disk partitioning |
| `sudo` | Privilege escalation |
| `su` | User switching |
| `chmod` | Permission changes |
| `chown` | Ownership changes |
| `kill` | Process termination |
| `pkill` | Process termination |

### Strict Mode Additional Blocks

| Command | Reason |
|---------|--------|
| `curl` | Network access |
| `wget` | Network access |
| `nc` / `netcat` | Network access |
| `ssh` | Remote access |
| `scp` | Remote file transfer |

## Dangerous Patterns

These patterns are always blocked:

```python
# Recursive force delete
"rm -rf /"  # Blocked

# Device file access
"> /dev/sda"  # Blocked

# Shell piping
"cat file | sh"  # Blocked
"cat file | bash"  # Blocked

# Command substitution
"$(dangerous_command)"  # Blocked
"`dangerous_command`"  # Blocked
```

## Path Restrictions

### Blocked Paths (Strict Mode)

```python
blocked_paths = {
    "/etc",      # System configuration
    "/var",      # Variable data
    "/usr",      # User programs
    "/bin",      # Essential binaries
    "/sbin",     # System binaries
    "/root",     # Root home
    "/home",     # User homes
    "/sys",      # Kernel interface
    "/proc"      # Process information
}
```

### Allowed Paths

```python
# Configure allowed paths
policy = SandboxPolicy(
    mode=SandboxMode.STRICT,
    allowed_paths={
        "/tmp",
        "/path/to/project",
        "/path/to/data"
    }
)
```

# Set up autonomy
autonomy = AutonomyModeHandler()

## Error Handling

### Timeout

```python
result = sandbox.execute("sleep 100", timeout=5)

if not result.success:
    if "timed out" in result.stderr.lower():
        print("Command timed out")
```

### Policy Violation

```python
result = sandbox.execute("rm -rf /")

if result.policy_violations:
    print("Command blocked by policy:")
    for violation in result.policy_violations:
        print(f"  - {violation}")
```

### Execution Error

```python
result = sandbox.execute("nonexistent_command")

if not result.success:
    print(f"Error: {result.stderr}")
    print(f"Exit code: {result.exit_code}")
```

## Best Practices

### When to Use Sandbox

| Scenario | Recommended Mode |
|----------|------------------|
| Running user-provided code | `strict` |
| AI-generated shell commands | `basic` |
| Processing untrusted data | `strict` |
| Local file operations | `basic` |
| Network-sensitive tasks | `network-isolated` |
| Trusted automation | `disabled` |

### Security Tips

1. **Start with strict** - Relax restrictions as needed
2. **Review violations** - Check what's being blocked
3. **Use network isolation** - When network isn't needed
4. **Set timeouts** - Prevent runaway processes
5. **Limit resources** - Prevent resource exhaustion

## Troubleshooting

### Command Unexpectedly Blocked

```python
# Check what's being blocked
violations = handler.validate_command("my_command")
print(violations)

# Adjust policy if needed
policy = SandboxPolicy(
    mode=SandboxMode.BASIC,
    blocked_commands={"rm", "sudo"}  # Reduced list
)
```

### Timeout Too Short

```python
# Increase timeout
result = handler.execute("long_running_command", timeout=300)

# Or in policy
policy = SandboxPolicy(max_cpu_seconds=300)
```

### Path Access Denied

```python
# Add to allowed paths
policy = SandboxPolicy(
    allowed_paths={"/path/to/needed/directory"}
)
```

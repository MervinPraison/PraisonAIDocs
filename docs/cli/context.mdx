The `context` command manages conversation context for AI agents.

## Usage

```bash
praisonai context [OPTIONS] COMMAND [ARGS]...
```

## Commands

| Command | Options | Description |
|---------|---------|-------------|
| `show` | `--verbose` | Show current context |
| `add` | | Add context from file or text |
| `clear` | | Clear current context |
| `stats` | `--agent`, `--json` | Show token usage / cache statistics |
| `compact` | `--agent`, `--threshold`, `--dry-run` | Compact the process-local store's per-agent history |
| `export` | `OUTPUT`, `--agent`, `--format` | Export the process-local store to a file |

<Warning>
`compact` and `export` operate on the **process-local** `get_global_store()`. That store is empty unless *this same process* populated it, so an ordinary `praisonai context compact` run over a store an agent run filled in another process will find nothing. See [Why is my store empty?](#why-is-my-store-empty) below.
</Warning>

## Examples

### Show current context

```bash
praisonai context show
```

### Add file to context

```bash
praisonai context add myfile.py
```

### Clear context

```bash
praisonai context clear
```

### Compact the store

```bash
praisonai context compact                 # compact every agent's history
praisonai context compact --agent agent-1 # compact one agent
praisonai context compact --dry-run       # show what would be compacted
```

`compact` cleans **per-agent** history only. It prints `Compaction complete (N agent(s)).` and exits `0` when work was done.

### Export the store

```bash
praisonai context export context.json           # snapshot to JSON
praisonai context export report.txt --format txt # human-readable summary
```

## Empty store

Because the store is process-local, these commands are honest about doing nothing:

| Situation | `compact` | `export` |
|---|---|---|
| Fully empty store | Exits `1`: `The context store is empty in this process.` | Exits `1`, writes **no** file |
| Shared-context only (no per-agent history) | Exits `1` (nothing to compact) | Succeeds — `snapshot()` serialises shared context |
| `--agent` matches nothing | Exits `1`: `no agent matching …` | — |

## Why is my store empty?

`get_global_store()` is an **in-memory singleton scoped to the current process**. The agent runtime does not write to it automatically — it only holds what a caller populated *in this process* via the [context API](/features/context-api#populate-the-store). A separate CLI process cannot see a store an agent run filled elsewhere; move it across processes with `snapshot()` / `restore()`. See [Context Management API → Scope](/features/context-api#scope-process-local-in-memory-opt-in).

<Note>
This CLI `context compact` is **not** the runtime `ContextCompactor` (the `/context compact` slash command / `ExecutionConfig(context_compaction=True)`). The CLI operates on the process-local `get_global_store()`; the runtime compactor trims a live agent's `chat_history`. See [Context Compaction](/features/context-compaction).
</Note>
